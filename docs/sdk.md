# Using the Go client on its own

`sdk/abs` is a plain Go client for the Audiobookshelf API, generated by [pandorest](https://github.com/katbyte/pandorest) from the API document below. It knows nothing about MCP. If you only want to talk to Audiobookshelf from Go, take it and ignore the rest.

```go
import "github.com/katbyte/abs-mcp/sdk/abs"

c, err := abs.New("http://nas:13378", os.Getenv("ABS_TOKEN"))
for item, err := range c.LibraryGetLibraryItemsEach(ctx, abs.LibraryID(libraryID)) {
	// every item of the library, a page at a time
}
shelves, err := c.LibraryGetUserPersonalizedShelves(ctx, abs.LibraryID(libraryID))
for _, shelf := range shelves.Answer {
	if shelf.Kind() == string(abs.ShelfTypeSeries) {
		series, err := shelf.AsSeriesShelf()
	}
}
```

## What it depends on

The standard library, pandorest's base client, and [go-kt's HTTP package](https://github.com/katbyte/go-kt/tree/main/httpc), which itself uses only the standard library. Nothing else is built into a program that imports it.

## How it behaves

- **Retries.** A read is asked for again when a gateway could not reach the server (502, 503, 504) or the connection dropped, three times in all. A write is sent once.
- **Logging.** It logs nothing unless handed a logger with `client.WithLog`. Then it traces every request and answer, with the API key blanked. abs-mcp hands it its own, so `ABS_LOG=trace` shows the traffic.
- **Errors.** A refusal carries Audiobookshelf's own words. `abs.IsNotFound` and `abs.IsForbidden` read the common ones.
- **Files.** A cover, a download or an audio file is handed over unread, to stream or save, so a multi-gigabyte audiobook does not have to fit in memory. A route that answers a word of text, such as the "OK" of a delete, is read and closed for you.
- **Another account.** `As` is a client for the same server with another account's key, for a call only that account can make, such as writing its listening progress.

## What it covers

Every route in Audiobookshelf's route table is in the API document, and the client has a method for each of the document's operations: libraries, items, authors, series, narrators, collections, playlists, progress, bookmarks, podcasts, provider search, RSS feeds, tags, genres, tasks, backups, playback sessions, notifications, email, API keys, sharing, settings and user administration.

`make apicheck` reads the route table out of the Audiobookshelf source and fails if the document lacks a route. So the coverage claim is checked, not just stated.

- **Ids.** Each kind of id is a type of its own, so a library id cannot be passed where a book's belongs.
- **Lists.** A list that pages has `Complete`, for every item at once, and `Each`, a page at a time as they are ranged over.
- **Dates.** Times, which Audiobookshelf writes as milliseconds since 1970, are read as dates.
- **Kinds of record.** A value of several kinds hands over the one asked for, checked against the field that names it.
- **Sets of values.** A field of fixed codes is a type with each code a constant, and `Known` says whether a value is one the document lists.

A few files are written by hand beside the generated ones, and say so at the top: what is Audiobookshelf's own about being talked to (`service.go`), reading an item's title and author as one line (`items.go`), and `As`.

## An API document read from the source

Audiobookshelf's own OpenAPI file covers under a quarter of its routes and stopped in 2024, and its [public API docs say they are unmaintained](https://api.audiobookshelf.org). So `api-defs/audiobookshelf-openapi-<version>.json` is written by reading the server source: every route, its parameters, its body fields, and what it answers, as far as the code says.

```bash
make spec SOURCE=../audiobookshelf   # a checkout of the release to read
make generate                        # the definitions in api-defs/audiobookshelf-<version>/, then sdk/abs
```

Where the code does not say a shape, the scan is told:

- **Answers saved from a real server** fill in what comes from a stored JSON column or an object the code fills in later, and correct the source where the server sent a fraction, a null or a field it does not mention (see [saving what Audiobookshelf answers](testing.md#saving-what-audiobookshelf-answers)).
- **Statements in `sdk/pandorest`**, each with the line of the source it comes from, give what the scan cannot follow: a typedef, a list of keys looped over, a record a middleware attaches, a value of several kinds (`unions.go`), the fixed codes a field takes (`enums.go`), and a field's type (`values.go`). One that the scan or the answers have caught up with is reported, so it can go.

What none of them says is left untyped. `make spec` reports how many answers it typed in full. `make gencheck`, and a unit test, fail when the definitions or the client are stale.

## Proved against a running server

The client is generated from the document, so the document is what has to be right. A live sweep calls every read of it against a real Audiobookshelf and fails an answer the client cannot read, and the live suite runs every call that changes something and reads back what it changed. See [testing.md](testing.md).
